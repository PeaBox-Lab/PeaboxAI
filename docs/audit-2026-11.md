# Code Review and Audit — November 2026 (v4.1.0)

A full review of the PeaBox AI Workbench codebase, performed with the app
running. This document records what was found, what was fixed in v4.1.0, and
what remains for later releases.

## Method

- Read every source file, doc, workflow and config in the repository.
- Created a virtual environment, installed dependencies, and compiled all modules.
- Ran the Streamlit app and the Settings page through Streamlit's headless
  `AppTest` harness and as a real server.
- Exercised the storage layer, attachment extractors (PDF, DOCX, XLSX, PPTX,
  text, images) and provider adapters against a mock Ollama HTTP server and
  mocked OpenAI/Anthropic SDKs. All 29 automated tests pass.

## Known limitations (not bugs, but be aware)

- **No streaming.** Responses arrive in one block; long generations look frozen.
  This is the single biggest UX gap. Targeted in v4.2.
- **No response regenerate / edit.** Rewrite the prompt to retry.
- **`reasoning_effort` is sent to all OpenAI-compatible endpoints** when
  reasoning is Low/Medium/High. Strict servers (some Groq/vLLM configs) reject
  unknown parameters. v4.2 should make reasoning provider-aware.
- **Cloud capability detection is name-based heuristics** (`vision`, `vl`,
  `claude`, ...). A misnamed model gets wrong capabilities. v4.2 should allow
  manual override per model.
- **SSH Ollama** spawns a `curl` per request over SSH; no connection reuse, no
  retries, and long `1800s` timeouts. Works, but it's the flakiest path.
  Consider a persistent SSH tunnel or native SSH port-forwarding in v4.3.
- **No secrets in CI artifacts**: keys live in the OS credential store (good),
  but `config.json` stores provider base URLs, hosts and key paths in plaintext
  (acceptable; documented).
- **`st.markdown` renders assistant output as markdown** — Streamlit escapes
  raw HTML by default, so XSS risk is low, but links are unsanitized. Fine for
  a local single-user app; revisit for team deployments (v5).
- **Single-user design.** No auth, no multi-tenancy, no request isolation. Do
  not expose to a network without putting it behind an authenticating proxy.
- **Empty placeholder assets**: `screenshots/*.png` are 2-byte files, and
  `ROADMAP.md`/README reference none of them. Capture real screenshots before
  announcing the v4.1 release (requires a visible desktop window).
- **Versioning debt**: upstream tags should follow the changelog (`v4.1.0`).

## Security notes

- API keys: stored via `keyring` (OS credential manager) — correct. Blank key
  in Settings retains the saved one — correct behavior now surfaced to the user.
- SSH: BatchMode with key auth, no host-key prompting hang. Consider documenting
  `known_hosts` pinning for unattended use.
- SQL: all queries parameterized. The `update_conversation` SET clause is built
  from an allowlist — safe.
- Attachments: extracted text is inlined into prompts (by design). Cloud
  providers will receive file contents — warned in README and docs.
- The app never executes model output. `docs/features.md` correctly states this.

## Verdict

PeaBox v4.1.0 is a coherent, honest, genuinely useful local-first workbench.
With this release it is in shape to publish: a valid license, accurate docs,
passing tests and a working CI pipeline. The highest-leverage next steps are
streaming chat, workspaces/RAG, and the model-comparison mode — in that order.
